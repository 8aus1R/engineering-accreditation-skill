# 批量Word制作与交付

## 输入与生成

- 以当前名册、逐题成绩、题源和确认模板建立学生×作业清单。核对重复身份、缺分、非法文件名、题数、计分步长及分项合计。
- 原始数据、经依据订正的数据与模拟分项分开记录。若只有总分而需要生成分项或答案，按模拟任务处理，见 [模拟与拆分](materials.md)。
- 复制已确认母版，仅改允许的身份、成绩、答案或评阅区域。每个字段绑定来源文件/单元格，保持题干、公式图片和无关格式。
- 写入、关闭、重新打开并核验完整后才把该文件列为完成，避免使用半写文件。

## DOC转换

用户要求Word97—2003 DOC时必须真正转换，不能改后缀。检查OLE签名`D0CF11E0A1B11AE1`只是必要的格式线索，仍需原生打开、内容检查与渲染。

DOCX转DOC可能改变公式换行、段落高度及兼容性；先逐模板转换并看最终页面，再对实际差异做局部修复。核对媒体数量、尺寸、完整公式和题干/答案位置，不无依据承诺像素相同。

## 批量核验与目录

- 全量检查学生×作业唯一性、最终文件名、最终正文题分、分组合计、总分及页数。模板固定部分可与已审阅母版比较，仅遮罩获准变化字段；这些字段另行全文检查。
- 文件名和目录层级按用户要求。重命名、重排或复制已验证文件时，保留旧→新相对路径及SHA-256，不重新生成正文。
- 事前检查重名与目标范围，事后比较全部文件哈希、各目录人数和总数，同步修改CSV里的相对路径。
- 正式交付仅含需要的文档、明确的模拟说明和必要核验材料；内部脚本、渲染图与临时文件留工作区。
- 新生成、模拟或按授权重新排版的作业还须执行 [作业格式与全量检查](homework-delivery-gate.md)。从实际答案独立判分，核对“答案支持的逐题得分＝题干标分”及“各题合计＝抬头总分＝Excel源值”；合计相同不证明答案应得该分。
- 修订后更新全部实际文件、清单和对应PDF/PNG哈希绑定。样例与最终DOC/DOCX各自检查，不把旧截图或转换前文件的结果沿用为当前交付证据。

## 附带的完整性检查器

```text
python skills/engineering-accreditation/scripts/verify_homework_delivery.py --root local-delivery --inventory inventory.json --csv scores.csv --path-column file
```

`local-delivery`是用户自行准备的本地交付目录，不包含在仓库中。最小清单结构如下；`file`为相对交付目录的路径，`sha256`须填真实文件的完整SHA-256：

```json
{
  "documents_inventory": [
    {"file": "assignment-01/DEMO-001.docx", "sha256": "replace-with-actual-sha256"}
  ],
  "documents": 1,
  "assignment_folders": [{"folder": "assignment-01", "documents": 1}]
}
```

`--csv`可重复指定；每个CSV都须覆盖全部清单文档。默认路径列名为“文件”，英文列可用`--path-column file`。默认清单名为“文件与分数核验记录.json”，也可通过`--inventory`指定。

检查器核对路径不越界、清单与实际Word文件集合、数量、逐文件哈希、可选目录数和CSV引用；`--require-binary-doc`额外检查DOC后缀与OLE头。

它不解析Word正文，不证明文件可打开、题分正确、签名完整或页面合格。没有启用二进制检查时，连DOCX包结构都不会校验。输出的`PASS`仅表示清单完整性检查通过，不能作为学术内容或版式通过的结论。输出含本地完整路径，公开前需脱敏。
